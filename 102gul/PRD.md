## 1. 제품 개요

### 1.1 문제 정의

1. 짧은 글귀는 SNS에서 빠르게 소비되지만, 다시 찾거나 차분히 읽기 어렵다.
2. 긴 글은 부담스럽고, 짧은 글은 광고·알고리즘·알림 때문에 집중이 깨진다.
3. 사용자가 직접 짧은 글을 쓰고 저장할 수 있는 가벼운 공간이 필요하다.
4. 학교 과제 시연에서는 복잡한 결제보다 인증, 데이터 저장, AI 생성, 사용자 작성 흐름이 명확하게 보이는 것이 중요하다.

### 1.2 비전

> 글결은 사용자가 하루 한 편의 짧은 글을 조용히 읽고, 마음에 드는 글을 저장하거나 직접 써서 간직하는 한국어 글귀 서비스다.

서비스의 핵심 경험은 `로그인 → 오늘의 글 읽기 → 저장 → 직접 쓰기 → 내 공간에서 다시 보기`이다.

### 1.3 목표

| 유형 | 목표 |
|---|---|
| 사용자 목표 | 사용자가 매일 한 편의 글을 부담 없이 읽고 저장할 수 있게 한다. |
| 제품 목표 | 읽기, 저장, 작성, 발견 피드, 마이페이지 흐름을 하나의 완성된 MVP로 제공한다. |
| 기술 목표 | Google OAuth 인증, Supabase DB/RLS, AI 글귀 생성, 로컬 실행 가능한 Next.js 앱을 구현한다. |
| 시연 목표 | Vercel 배포 없이 `localhost:3000`에서 전체 플로우를 보여준다. |

## 2. 범위

### 2.1 MVP In Scope

- Google 계정으로 로그인
- 오늘의 글귀 조회
- AI 또는 수동 seed 기반 오늘의 글귀 제공
- 글 저장/저장 해제
- 저장한 글 목록 조회
- 사용자가 직접 글 작성, 수정, 삭제
- 공개 글을 모아보는 발견 피드
- 마이페이지
- 로컬 개발 서버에서 시연
- Supabase RLS 기반 사용자 데이터 보호

### 2.2 Out of Scope

- 결제, 구독, 프리미엄, Toss Payments 연동
- Vercel 또는 외부 배포
- 이메일 회원가입 필수화
- 팔로우, DM, 실시간 채팅
- 푸시 알림
- 관리자 CMS
- 외부 글귀 데이터 무단 수집
- 모바일 앱 개발

## 3. 타겟 사용자

### 3.1 Primary Persona — 감정 정돈러

- 출퇴근길이나 자기 전 짧은 시간에 차분한 문장을 읽고 싶다.
- 인스타그램이나 블로그에서 마음에 드는 문장을 캡처하지만 다시 찾기 어렵다.
- 복잡한 커뮤니티보다 조용한 개인 공간을 선호한다.

핵심 니즈: `마음에 든 글을 저장하고 다시 볼 수 있으면 좋겠다.`

### 3.2 Secondary Persona — 조용한 창작자

- 긴 글보다는 짧은 문장을 쓰고 싶다.
- 공개 SNS에 올리기에는 부담스럽다.
- 공개/비공개를 직접 선택하고 싶다.

핵심 니즈: `부담 없이 짧게 쓰고, 필요하면 다른 사람에게 공개하고 싶다.`

## 4. 사용자 여정

### 4.1 첫 방문 및 로그인

```text
랜딩 페이지
  → Google로 로그인
  → OAuth 동의
  → /auth/callback
  → 오늘의 글 화면
```

성공 기준:

- 사용자는 이메일/비밀번호 입력 없이 Google 계정으로 로그인할 수 있다.
- 로그인 완료 후 서비스 내부 화면으로 이동한다.
- 새 사용자는 자동으로 `profiles` 레코드가 생성된다.

### 4.2 오늘의 글 읽기

```text
오늘의 글 화면
  → 제목과 본문 읽기
  → 저장 버튼 클릭
  → 저장 완료 상태 확인
  → 마이페이지에서 다시 보기
```

성공 기준:

- 오늘 날짜에 해당하는 글이 1개 노출된다.
- 글이 없으면 서버에서 AI 또는 fallback seed로 생성한다.
- 저장 상태가 사용자별로 유지된다.

### 4.3 직접 글 작성

```text
쓰기 화면
  → 제목 입력
  → 본문 입력
  → 태그 입력
  → 공개/비공개 선택
  → 저장
  → 내 글 목록 또는 발견 피드에서 확인
```

성공 기준:

- 제목은 40자 이하, 본문은 600자 이하로 제한한다.
- 공개 글은 발견 피드에 노출된다.
- 비공개 글은 본인만 볼 수 있다.

### 4.4 마이페이지

```text
마이페이지
  → 내 프로필 확인
  → 저장한 글 확인
  → 내가 쓴 글 확인
  → 수정/삭제
  → 로그아웃
```

성공 기준:

- 내 저장 목록과 내 작성 글이 분리되어 보인다.
- 다른 사용자의 비공개 글은 접근할 수 없다.

## 6. UX/UI 원칙

### 6.1 조용한 방

- 광고, 알림, 과한 토스트를 사용하지 않는다.
- 한 화면에 하나의 주 행동만 둔다.
- 저장, 작성 완료 같은 피드백은 작고 차분하게 표현한다.

### 6.2 타이포그래피 중심

- 본문은 한글 세리프 계열을 우선 사용한다.
- 본문 줄간격은 넓게 유지한다.
- 글보다 버튼, 카드, 장식이 더 튀지 않게 한다.

### 6.3 모션

- 글 등장은 0.6~0.8초 페이드 인으로 처리한다.
- 호버 시 크기 변화보다 색상/명도 변화만 사용한다.
- 시연 안정성을 위해 복잡한 애니메이션은 P1로 미룬다.

### 6.4 화면 구성

| 화면 | 목적 | 주요 CTA |
|---|---|---|
| `/` | 서비스 소개 | Google로 시작하기 |
| `/login` | 로그인 | Google로 로그인 |
| `/today` | 오늘의 글 읽기 | 저장하기 |
| `/feed` | 공개 글 발견 | 저장 / 읽기 |
| `/write` | 글 작성 | 저장하기 |
| `/me` | 내 공간 | 저장 글 보기 / 내 글 관리 / 로그아웃 |

## 7. 성공 지표

### 7.1 시연 성공 기준

| 항목 | 성공 조건 |
|---|---|
| Google 로그인 | 실제 Google 계정으로 로그인 성공 |
| 세션 유지 | 새로고침 후에도 로그인 유지 |
| 보호 라우트 | 로그아웃 상태에서 내부 페이지 접근 시 로그인 화면으로 이동 |
| 오늘의 글 | 로그인 후 오늘의 글 표시 |
| 저장 | 저장 후 마이페이지에서 확인 가능 |
| 작성 | 새 글 작성 후 내 글 목록에 표시 |
| 공개 피드 | 공개 글이 발견 피드에 표시 |
| RLS | 다른 사용자의 비공개 글 조회 불가 |
| 로컬 실행 | `http://localhost:3000`에서 모든 플로우 시연 가능 |

### 7.2 과제 평가 관점

- 인증: Google OAuth가 실제로 동작하는가
- DB: 사용자별 데이터가 저장되고 조회되는가
- 보안: RLS로 데이터 접근이 통제되는가
- AI: 오늘의 글 생성 또는 seed fallback 구조가 있는가
- UX: 읽기 중심의 감성 UI가 구현되었는가
- 문서: PRD/TRD/README가 실행 방식과 구현 범위를 정확히 설명하는가

## 8. 릴리즈 계획

### Phase 1 — Local Foundation

기간: 1주차

작업:

- 의존성 설치
- `.env.local` 구성
- Supabase 프로젝트 연결
- Google OAuth 설정
- 로그인/콜백/로그아웃 구현
- 보호 라우트 구현

Exit Criteria:

- Google 로그인 후 `/today`에 접근 가능하다.
- 로그아웃 후 보호 페이지 접근 시 `/login`으로 이동한다.

### Phase 2 — Data & Reading

기간: 2주차

작업:

- Supabase migration 적용
- `daily_quotes`, `saved_items`, `profiles` 연결
- 오늘의 글 조회 API 구현
- 저장/해제 구현

Exit Criteria:

- 오늘의 글이 표시되고, 사용자가 저장할 수 있다.

### Phase 3 — Write & Feed

기간: 3주차

작업:

- 글 작성/수정/삭제
- 공개/비공개 처리
- 발견 피드
- 마이페이지

Exit Criteria:

- 사용자가 직접 글을 작성하고, 공개 글은 피드에 노출된다.

### Phase 4 — Polish & Demo

기간: 4주차

작업:

- UI/모션 마감
- seed 데이터 준비
- RLS 테스트
- README 실행법 정리
- 시연 스크립트 작성

Exit Criteria:

- `npm run dev`만으로 로컬 시연이 가능하다.

## 9. 제약사항과 가정

### 9.1 제약사항

- Vercel 배포는 하지 않는다.
- 결제 기능은 구현하지 않는다.
- Google 로그인은 반드시 구현한다.
- 서비스는 한국어만 지원한다.
- 사용자 입력은 일반 텍스트만 허용한다.
- 외부 글귀를 무단으로 수집하지 않는다.

### 9.2 가정

- Supabase는 hosted project를 사용하고, Next.js 앱만 로컬에서 실행한다.
- 시연자는 인터넷 연결이 가능한 환경에서 Google OAuth를 진행한다.
- 시연 계정은 최소 2개를 준비해 RLS를 검증한다.
- AI API 장애 시에도 seed fallback으로 오늘의 글을 보여준다.
